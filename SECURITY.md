# Security

FestiPlan has no accounts, so its threat model is small: protect the AI quota, keep
plans editable only by people holding the edit key, never let user text steer the
model, and never leak credentials. Every control below is implemented in code. The
Tests column names the tests that exercise it; where a control is cloud configuration
that unit tests cannot reach, the column says so.

## Reporting

Please open a private security advisory on GitHub or email the maintainer. Do not
file public issues for vulnerabilities.

## Controls

| Risk | Control | Code | Tests |
|---|---|---|---|
| Credential leakage | Production uses the Cloud Run service identity (ADC) for Vertex AI and Firestore. No API keys exist in production. `GEMINI_API_KEY` is local-only and server-only, never `NEXT_PUBLIC_`. Deploys use Workload Identity Federation, so no service-account keys exist. | `src/lib/ai/client.ts`, `.github/workflows/deploy.yml` | `tests/ai/client.test.ts` (backend selection). WIF itself is cloud configuration with no unit test. |
| Over-privileged runtime | The service runs as a dedicated `festiplan-runtime` service account holding only `roles/aiplatform.user`, `roles/datastore.user` and `roles/logging.logWriter`. The deployer may act as that one account (`iam.serviceAccountUser` granted on the SA). The deploy passes `--service-account` when the `GCP_RUNTIME_SA` repo variable is set; projects bootstrapped before it existed keep the default compute SA until the script is re-run. | `scripts/gcp-bootstrap.sh`, `.github/workflows/deploy.yml` | IAM configuration, so no unit test. The deploy smoke test checks `/api/health` after every deploy. |
| Oversized / malformed bodies | A streaming byte cap per route (8 KB plan, 16 KB patch, 2 KB refine, 1 KB vendors) is checked before parsing. `application/json` is required. Zod strict objects reject unknown keys. | `src/lib/security/body.ts`, `src/lib/contracts/input.ts` | `tests/security/body.test.ts`, `tests/api/*.test.ts` (413 / 415 / 400) |
| Quota abuse / DoS (per client) | Fixed-window limits per client: plan 5/min, refine 10/min, vendors 10/min, patch 30/min, reads 120/min, `.ics` 60/min, each answered with 429 and `Retry-After`. The client IP is the `X-Forwarded-For` entry appended by Cloud Run's front end (rightmost, `TRUSTED_PROXY_HOPS`), so a client cannot spoof its way around the limit. IPv4 is keyed per address. IPv6 is keyed on its **/64** network, because one subscriber holds a whole /64, and IPv4-mapped IPv6 is keyed as the IPv4 address. | `src/lib/security/rate-limit.ts`, `src/lib/security/ip.ts`, `src/lib/server/http.ts` | `tests/security/rate-limit.test.ts`, `tests/security/ip.test.ts`, `tests/security/origin.test.ts`, `tests/server/http.test.ts`, `tests/api/plan.test.ts`, `tests/api/vendors.test.ts` (two addresses in one /64 share a window) |
| Quota abuse / DoS (many clients) | Each instance has a global ceiling of 120 AI-backed requests per minute (× `RATE_LIMIT_SCALE`), shared by plan creation, refine and vendors. It is checked after the per-client limit and after validation, so junk requests do not spend it. Over the ceiling the server answers 503 with `Retry-After` and a plain-language message. Cloud Run is capped at 5 instances. Plan output is bounded by `maxOutputTokens` (8192 for English, 16384 for other languages). A reply cut off at that limit is asked for once more with 1.5× the budget (at most 24576), without resending the cut-off text. | `src/lib/server/http.ts` (`aiGlobalLimit`), `src/lib/ai/plan-model.ts`, `.github/workflows/deploy.yml` | `tests/api/ai-ceiling.test.ts`, `tests/ai/plan-truncation.test.ts` |
| Open-ended Maps proxy | `POST /api/vendors` takes only `{ planId, category }`. The city and event type are read from the stored plan, so the endpoint cannot run arbitrary Maps searches. An unknown plan returns 404. | `src/app/api/vendors/route.ts`, `src/lib/contracts/input.ts` | `tests/api/vendors.test.ts` |
| Cross-site request forgery | State-changing routes require a same-origin `Origin` header, or `Sec-Fetch-Site: same-origin` when there is no `Origin`. | `src/lib/security/origin.ts` | `tests/security/origin.test.ts`, `tests/api/*.test.ts` (403) |
| Unauthorised edits | Each plan gets a 256-bit random edit key, returned once. Only its SHA-256 is stored, and the comparison is timing-safe. Share links are read-only. The edit link carries the key in the URL fragment, which browsers never send to servers. | `src/lib/security/edit-key.ts`, `src/lib/client/edit-keys.ts` | `tests/security/edit-key.test.ts`, `tests/server/plan-service.test.ts`, `tests/api/plan-id.test.ts`, `e2e/planner.spec.ts` (read-only viewer) |
| Prompt injection | User text reaches Gemini only inside a delimited block labelled as untrusted data, with delimiter sequences stripped. The system instruction tells the model to ignore instructions inside it. Model output is Zod-validated and can never set amounts or dates. | `src/lib/ai/prompts.ts` | `tests/ai/prompts.test.ts`, `tests/ai/plan.test.ts`, `tests/ai/vendors.test.ts` |
| Hallucinated vendors | Only places returned in Maps grounding metadata (title plus an `https` Maps URI) are rendered. No model text is shown as a vendor. | `src/lib/ai/vendors.ts` | `tests/ai/vendors.test.ts` |
| Tampered budgets | PATCHed allocations must cover the same categories and sum to the same total. Otherwise the server answers 422 and writes nothing. | `src/lib/engine/budget.ts` (`applyEdits`), `src/lib/server/plan-service.ts` | `tests/engine/budget-edit.test.ts`, `tests/server/plan-service.test.ts`, `tests/api/plan-id.test.ts` |
| Lost updates | Every edit is one atomic read-modify-write through `PlanStore.mutate`: a Firestore `runTransaction` (read, decide, then `set` only when there is a next plan) or a no-await critical section in memory. Concurrent saves from two phones both persist. | `src/lib/store/firestore.ts` (`loadFirestore`, `mutate`), `src/lib/store/memory.ts` | `tests/store/firestore-sdk.test.ts` (the real transaction code against a mocked `@google-cloud/firestore`: one read and one write per edit, no write for 403 / 404 / 422), `tests/server/concurrency.test.ts` |
| XSS | Nonce-based CSP from `src/proxy.ts`. Every page request gets a fresh 128-bit nonce, and the policy is `script-src 'self' 'nonce-…' 'strict-dynamic'`, with no `'unsafe-inline'` for scripts. `'unsafe-eval'` is added in development only. The rest of the policy: `default-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, `connect-src 'self'`, and `upgrade-insecure-requests` in production. Next.js stamps the nonce on its own scripts, and `'strict-dynamic'` lets them load the lazy WebGL chunks. Pages render per request (`connection()` in the root layout) so each one gets its own nonce. Styles allow `'unsafe-inline'`. React escaping is used throughout, with no `dangerouslySetInnerHTML`. API responses carry `default-src 'none'`. | `src/proxy.ts`, `src/lib/security/csp.ts`, `src/app/layout.tsx`, `next.config.ts` | `tests/security/proxy.test.ts` (header shape, per-request nonce, dev/prod differences, matcher skips `/api`, static assets and prefetches), `tests/security/headers.test.ts` |
| Clickjacking, sniffing, leaks | `frame-ancestors 'none'` plus `X-Frame-Options: DENY`, HSTS, COOP `same-origin`, `nosniff`, a strict referrer policy and a restrictive Permissions-Policy. Shared plans send `X-Robots-Tag: noindex`. | `next.config.ts` | `tests/security/headers.test.ts`, `e2e/planner.spec.ts` (noindex) |
| Direct database access | Firestore security rules deny all client access. Only the server (Admin SDK) reads and writes. | `firestore.rules` | No test: rules are deployed configuration. |
| Data retention | Plans expire via a Firestore TTL policy 180 days after creation. Logs contain no user text, only operational fields and, for AI calls, token counts. | `src/lib/server/plan-service.ts`, `src/lib/server/log.ts`, `src/lib/ai/plan.ts` | `tests/server/plan-service.test.ts` (`expireAt`), `tests/server/log.test.ts`, `tests/ai/plan-truncation.test.ts` (token log carries numbers, not the brief). The TTL policy itself is cloud configuration. |
